## 1. 产品定位与目标

面向有走失、跌倒等外出安全风险、需要家属远程监护的老年人。通过随身设备感知运动、位置、周围环境及现场图像，形成可解释的多模态安全评估，分级提示风险，并帮助家属及时确认异常与联系老人。

核心价值不是医学诊断或孤立地展示传感器，而是：**及时发现异常、了解老人所在位置及周围情况、解释风险、帮助家属采取行动。** 环境监测是外出安全的辅助；温湿度和气体监测彼此同级。首版综合评估优先显示风险等级和依据，不要求数值评分。

核心闭环：设备采集 → 校验/存储 → 单项检测与多模态分析 → 风险分级 → 通知家属 → 家属确认、查看证据、决定是否拨号 → 记录处置结果。

非目标：医疗诊断、疾病预测、无证据的健康安全百分比、自动拨打设备或公共急救电话、未经授权的监控、把静态照片伪装成实时视频。

| IMU流 | 50Hz，25点一批（约0.5秒），100点队列；断网清空，旧批丢弃，不重传；后端按设备及启动会话分开建窗 | 模型需要连续样本；掉线显示未知而不是零分；原始六轴默认不落库（可配置），不能承诺完整六轴历史回放 |

证据：`app.js` 顶部常量及 `poll`、`queries.py::insert_sample_ratelimited`、`config.py`、`app.py::latest/_simplify_track`、`ingest.py::handle`、`photos.py::_db`、`imu_stream.cpp`、`imu.py::accept`。

### 2A.6 现有AI模型资产与正确使用范围

`ml/train_sisfall.py`、`backend/fall_ml.py`、`backend/imu.py`、`backend/models/sisfall_rf_v1.json` 与 `ml/reports/sisfall_rf_v1.json` 构成现有训练及推理资产。不是通用多模态模型：当前仅使用六轴运动特征。50Hz、150样本窗（约3秒）、步长25、40个特征；随机森林48棵树、最大深度8；阈值0.8；后端连续两次高分且8秒去重窗口满足条件时生成影子事件；模型加载失败或样本断档不会控制设备侧报警。

随包报告（2026-10-21，模型`sisfall-rf-v1-20261021`）记录：4505条试验记录，按受试者划分训练/验证/测试。测试375次跌倒试验中346次在弱标签时间规则下匹配（92.27%），29次未匹配；512次日常活动试验、约2.28小时的评估中记录0次事件级误报。该报告同时列出窗口级混淆矩阵中的2个假阳性窗口，事件级与窗口级口径不同。以上是随包离线报告值，本轮未重训/复算，不代表真实佩戴效果。报告明确限制：主要是年轻人模拟跌倒、腰部佩戴、按加速度峰值作弱时间标签、未验证真实胸部佩戴/MPU6050域差异、日常活动时长短，模型分数未校准。不能解释为老人安全概率、医疗诊断或最终综合风险；首版等级文字解释保留模型辅助来源，并允许技术详情查看现有模型分数，不作为首版总分。

## 7. 摄像头专项交互与保护要求（本版重点）

### 7.1 三种来源

| 来源 | 含义 | 产品状态 |
|---|---|---|
| 被动事件触发 | 设备检测到配置异常后自动拍照上传，家属不必操作 | 保留；当前源码明确FALL、AIR触发，其他事件待批 |
| 主动拍照 | 授权子女/家属在客户端发出拍照请求，设备拍照并返回上传结果 | 用户确认已有主动调用设计；当前源码有本地手动接口，跨网云端命令待设计/验证 |
| 定时拍照 | 设备按周期拍照 | 现有代码5分钟周期；正式版是否保留、频率及权限单独评审 |

查看已经上传的照片与触发一次新拍照应分开：前者不要求设备重新拍摄，后者受权限、在线状态、保护间隔和设备可用性约束。这是静态照片，不是视频直播。不承诺画面能拍到老人或确认伤情。

### 7.2 主动拍照流程

1. 家属进入现场照片页，显示最近照片及拍摄时间/来源；点击“请求拍照”（明确为设备新拍一张）。
2. 系统检查权限、设备在线、摄像头可用性及保护状态；不可用时解释原因，若设备返回剩余等待时间则展示倒计时。
3. 接受请求后显示“请求已提交/等待设备”，收到设备反馈后显示“拍摄中/上传中”或可证实的最近进度；没有细粒度反馈时使用“等待设备返回”，不虚构进度。
4. 收到与本次请求相关的照片才标记完成并更新展示；超时、拍摄失败、上传失败或请求取消/过期按实际反馈区别显示。
5. 进入保护等待时禁用重复拍照操作，仍允许查看旧照片、地图、报警及联系老人；再次可用由设备/后端状态决定。

### 7.3 保护规则

- 用户确认设计有拍照时间间隔，目的为降低连续工作导致的发热/损坏风险。保护参数必须以硬件验证确定；不承诺仅靠间隔即可完全避免损坏。
- 最小拍照间隔T_min、最长连续工作时间（如需）、超时T_req、等待时间起算点、重复请求处置、多设备并发、多个家属同时请求、被动与主动拍照冲突规则均待核验与批准。
- 建议设备端执行不可绕过的最终保护；云端协调同一设备的请求，客户端据权威状态反馈，不仅依赖按钮禁用。异常拍照建议优先调度，但不可绕过经验证的硬件安全边界。
- 达到保护限制时，应按批准策略拒绝或合并/延后请求；记录照片缺失原因。紧急报警应独立发送，不因为等待照片而延迟发出。
- 已有5分钟定时拍照周期不等于最小保护间隔。不得用5分钟作为正式主动调用冷却时间，除非专项批准。

### 7.4 UI状态表

| 状态 | 建议显示 | 可用操作 |
|---|---|---|
| 无图像 | 暂无照片 | 条件满足时请求拍照 |
| 有历史照片 | 照片来源＋拍摄时间＋非实时标识 | 查看；符合条件时请求新照片 |
| 已提交/等待 | 等待设备返回 | 查看已有照片；避免重复提交 |
| 拍摄/上传 | 仅显示已获得的真实进度 | 禁止重复提交 |
| 保护等待 | 摄像头保护中；如有权威剩余时间，显示倒计时 | 查看旧照片，稍后重试 |
| 离线/故障 | 设备离线/摄像头不可用 | 查看历史、联系老人 |
| 超时/失败 | 原因及是否可重试 | 按保护状态重试 |
| 无权限 | 无访问权限，不显示照片及敏感信息 | 返回/申请授权（如有） |

## 8. 风险评估与分级报警

| 等级 | 语义 | 行为候选 |
|---|---|---|
| L0 正常 | 有效且必要数据未发现当前规则定义的异常 | 常规记录，不保证绝对安全 |
| L1 关注 | 轻度异常或需持续观察 | 界面提示、趋势记录 |
| L2 预警 | 持续或组合风险达到预警规则 | 主动通知家属、提供核查入口 |
| L3 紧急 | 达到批准的高危条件 | 高优先级通知家属、突出联系入口，仍由家属决定拨号 |
| 监测不可用（非风险等级） | 数据缺失、过期、离线、传感器错误等 | 显示原因，不把既有未处理风险清零；按批准规则提示监测异常 |

候选判定：轻度运动异常L1；持续空气异常L2；符合经验证跌倒高危规则L3；异常冲击、姿态变化、静止等可组成证据；多种环境异常的组合等级待验证。主动拨号不自动等同于云端求救事件，只有加入并验证独立求救同步能力后才能使用相应规则。电子围栏尚未批准为首版核心能力。

分级逻辑必须保留单项判定、组合判定和高危优先裁决。证据不足不降低已触发的高危风险；独立高危报警不等待视觉、模型或报告生成。恢复阈值、持续时间、规则去重、升级条件及通知重复策略要经实际验证，不能由UI直接定值。

AI路线：P0先采用可解释规则及现有辅助模型；后续再按实测价值决定训练专用模型或外部API。外部AI不可作为唯一紧急报警决策源，模型失败时保留规则结果。报告中区分事实、规则判断、模型推断和建议；第三方数据处理须另行授权及评审。

## 9. 报警及沟通核心流程

### 9.1 报警处置（Android/Windows共用事件状态）

设备发现异常 → 事件进入系统 → 规则判定/必要时组合分析 → L2/L3通知 → 家属从通知或报警中心进入详情 → 查看事件、位置、照片（若有） → 确认收到 → 自主选择电话联系/其他核查 → 填写处置结果 → 关闭事件。

未送达、未确认、待处理与风险恢复应区分。首版不默认自动拨号或自动呼叫急救机构。多人确认、未确认升级提醒的具体策略待批；重复通知不得创建重复事件。确认不等于老人安全，关闭不删除原始记录，恢复不自动等于已处置。

### 9.2 联系老人

Android：展示设备/联系人与拨号意图，家属自行确认或取消，优先使用经评审可用的系统拨号方式。Windows：提供号码、可用的联系入口/复制号码或使用手机拨号的指引；不得在未确定Windows通话能力时承诺可在桌面直接接通。实际振铃、接通、挂断状态仅在硬件或系统提供可靠回传时展示；否则仅记录发起联系操作，不虚构通话结果。

## 11. 数据与非功能需求

- 设备身份与授权隔离：账号、家庭、成员、设备、遥测、报警、照片、联系人及处置记录有可追溯关联；不允许客户端直接访问数据库。
- 数据字段：传感器名、值、单位、采样/接收时间、有效性及来源；GPS坐标系与更新时间；照片来源、拍摄/上传时间、关联事件/请求；报警等级、规则版本及处置记录。具体API和表结构由架构负责人负责。
- 可靠性：网络断开不影响设备侧已有本地检测；事件可靠上报、去重、队列溢出与重启数据恢复能力待设计测试；平台提供离线/缺失状态。不能保证所有报警在所有情况下送达。
- 隐私：位置、照片、电话号码及老人身份最小化采集；授权验证、传输保护、访问审计、保留期限及解绑/删除机制待安全评审。生产通知避免未经批准将精确位置或照片暴露在锁屏上。
- 性能：数据刷新周期、通知时延、照片返回时延、查询范围、设备续航及负载容量待实测冻结。UI不承诺固定时延或秒级实时。
- 可维护性：统一业务语义和版本化接口；规则及模型可追溯；双端安装、升级、异常恢复和回归测试列入正式发布验收。

4. 发布验收：真实设备、网络异常、权限、数据质量、隐私、恢复、长时运行、安装升级/卸载等通过批准门槛；记录测试版本、设备、条件、预期、实际、严重等级与修复建议。未经批准不得发布或合并主分支。
